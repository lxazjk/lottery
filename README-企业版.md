# 幸运盛典 · 企业号码抽奖

基于 [moshang-ax/lottery](https://github.com/moshang-ax/lottery) 改造，使用 Vue 3、Vite 和 Three.js CSS3D。抽奖与保存均在浏览器内完成，构建后是纯静态网页，无需运行抽奖后端。保留原 MIT 许可证。

## 本场活动

- 号码范围：1–200，显示为 `001–200`，例如 `007` 表示 7 号。
- 特等奖 1 个、一等奖 2 个、二等奖 2 个、三等奖 3 个，共 8 个中奖名额。
- 主抽奖画面显示奖项与中奖号码；点击“查看奖品”展示每档奖品的图片、名称、名额及对应中奖号码。
- 奖品对应：特等奖为 Redmi 平板，一等奖为小米智能音箱 Pro，二等奖为米家负离子速干吹风机 H300，三等奖为小米充电宝 10000mAh。
- 默认从三等奖到特等奖，每次抽取 1 个号码。也可点击左侧未抽完的奖项切换。
- 一个号码在整场活动中只能中奖一次，跨奖项排重；已中奖号码从号码球中隐藏。8 个名额全部用完后不能继续抽取。
- 中奖者缺席时可重新抽奖，只替换其所在的一个名额；缺席号码退出本场活动，其余中奖者保持不变。

## Mac 启动

双击项目中的 `启动抽奖.command`，浏览器会打开本地活动页面：

http://127.0.0.1:9018/

请保留启动时的终端窗口。首次运行需要 Node.js 20 或更高版本与网络，以安装依赖；依赖安装后，抽奖、动画、音乐、数据保存均可在本机离线使用。此处启动的服务只负责提供静态文件，仅监听本机。

也可在终端运行：

```sh
cd /Users/jk.zhou/Projects/enterprise-lottery
npm run setup  # 首次安装依赖；已有 node_modules 时不必执行
npm run build
npm start
```

开发界面：`npm run dev`，地址以 Vite 输出为准（默认 9000）。
检查抽奖逻辑：`npm test`。

## 现场操作

1. 默认选中三等奖，点击“开始抽奖”后先展示三等奖的充电宝图片与名称，再点击“开始抽取三等奖”，3D 号码球才开始旋转。每档奖第一次开始前只展示该档的奖品，同一档后续名额连续抽取不重复展示；刷新后恢复活动时会重新展示当前奖品。
2. 点击“停止 · 揭晓幸运号码”，展示本次中奖号码。
3. 点击“继续抽取”，抽该奖项的下一位；该档抽完后按钮切换到下一奖项，点击后先展示下一档的奖品，再确认开始。
4. 右上角“中奖名单”查看全部结果，可导出 CSV 名单（Excel 可打开），也可下载包含历史活动的 JSON 备份。
5. `Space` 开始/停止，`F` 全屏；右上角可手动开启/关闭背景音乐，默认关闭。
6. “重置活动”需要二次确认，会先备份旧结果，再将全部名额归零。
7. 点击奖项栏右上角“查看奖品”，即可查看四档奖品与已揭晓的中奖号码，查看后点“返回抽奖”继续。
   该入口为金色大按钮。
8. 底部“重置活动”旁也可点击“开始抽奖”，旋转时切换为“停止抽奖”。全部名额抽完后，点击该按钮可确认开始新一轮；系统会先备份旧名单，再清空进度并展示三等奖奖品，确认开始后号码球才旋转。
9. 若中奖者未到场，点击中奖结果下的“无人到场 · 重新抽奖”，或在“中奖名单”中点击对应号码旁的重抽图标，确认后号码球开始旋转，再点击“停止 · 揭晓幸运号码”完成补抽。取消确认或在停止前刷新页面，会保留原结果。即使 8 个名额已抽完，也可替换缺席者。

## 界面设计

深墨绿黑底、香槟金点缀，中文宋体主标题与数字字体搭配；细颗粒纹理、轨道线和微光让画面有活动现场的仪式感。

左侧四档奖项显示抽取进度，并突出当前奖项；中央为 200 张唯一号码卡组成的 3D 球体，开奖时淡出背景，突出大号金色中奖号码与短暂彩带；底部显示号码范围与总进度。电脑、笔记本和手机窄屏均有适配，并尊重系统“减少动态效果”偏好。

## 防重复与本机保存

每次开奖先排除当前活动的所有中奖号码，再用浏览器 Web Crypto 生成等概率随机索引。候选筛选、开奖与保存放在同一个 IndexedDB 读写事务内，保存成功后才展示中奖结果。相同请求 ID 重试返回原结果，不消耗新名额。

补抽将原中奖记录移入缺席记录，并同时保存替补号码，奖项和总名额不变；缺席号码也会从后续候选池及号码球中排除。刷新后继续排除这些号码；CSV 仅包含当前有效中奖者，JSON 备份包含缺席与替换历史。保存失败时原结果保留，可重试确认；其他标签页已替换同一人时，不会重复补抽。

刷新页面、关闭再打开后会继续读取进度。同一浏览器、同一网址的多个标签页共用一个候选池，事务会串行处理同时开奖，并通知其他页面更新进度。其他页面开始新活动时，旧活动中尚未完成的抽取会取消。

只有确认“重置活动”或“开始新一轮”才会重新启用所有 200 个号码。重置前会在同一事务中将旧活动存入历史备份；“下载备份”可将当前及历史活动保存成 JSON 文件。当前页面不提供备份导入按钮。

记录存于当前浏览器的网站数据中：清理网站数据、使用无痕窗口、换浏览器、换网址或换电脑会使用独立的记录。现场请固定一台电脑、一个浏览器和同一网址，活动前后下载名单或备份；此版本不提供跨设备统一排重或共享名单。

旧本地版本迁移：第一次在 `http://127.0.0.1:9018/` 打开新版且浏览器尚无活动记录时，会尝试从仍运行的旧服务读取一次进度并复制到浏览器，原 `server/cache/` 文件不修改。之后不再调用旧抽奖接口。直接使用静态服务的全新安装从空活动开始。

活动配置位于 `product/src/lottery/config.json`，修改后重新构建。在已经开奖的活动中改变号码范围或名额会触发保护并停止抽奖，应先完成并备份旧活动，再准备新的活动。

## 挂到域名

`npm run build` 生成的 `product/dist/` 可以部署到 GitHub Pages、Cloudflare Pages 等静态托管服务，再绑定 `lottery.lxazjk.me`。托管端只提供 HTML、JS、CSS、奖品图片和音乐，无需购买云服务器，也无需部署 `server/`。

静态资源使用相对路径，可用于独立子域名或项目子路径。请通过 HTTPS 访问（本机 `localhost` 和 `127.0.0.1` 可使用 HTTP），以使用安全随机数等浏览器能力。不同访问者各自使用自己的活动记录；不是所有访客共用一场抽奖。

本仓库使用 `vue` 分支保存源代码、`codex/pages` 分支保存构建产物。更新源代码并提交后，运行 `npm run publish:pages`，脚本会先测试、构建，再将纯静态文件推送到发布分支。GitHub Pages 的发布源应选择 `codex/pages` 分支的根目录。源代码中的中奖记录、本地缓存及开发依赖均不进入发布分支。

如当前网络需要本地代理，可通过 `LOTTERY_GIT_PROXY=http://127.0.0.1:7897 npm run publish:pages` 运行发布命令；不要把访问凭据写入仓库。
